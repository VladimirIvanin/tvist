## События

**EV01 / TVIST-AUDIT-001. Рекурсивный `once` повторно входит в обработчик.** Опции слайдера не влияют. Подписаться через `slider.once('audit:reentrant', handler)`. Внутри handler увеличить `calls` и вызвать `slider.emit('audit:reentrant')`, пока `calls < 3`. Один внешний `emit` должен дать `calls === 1`. Получено `3`. Такой же результат даёт прямой тест EventEmitter. В `once()` wrapper снимается после вызова пользовательского handler. Проверить порядок снятия при повторном входе, в том числе если callback выбрасывает исключение. Отдельно сохранить доставку прочих слушателей текущего события. [Свежая попытка](../../.tmp/audit/2026-10-31T22-08-47-462Z-smoke-all-60ee2a3a/EV01-chromium.json), [public case](../../tests/audit/input.ts#L915), [unit oracle](../../tests/audit/oracles.audit.ts#L11), [EventEmitter.once](../../src/core/EventEmitter.ts#L83).

**EREG-001 / TVIST-AUDIT-032. Читающий подписчик `videoEnded` добавляет лишний переход.** Создать три слайда с HTML video, `speed:0`, `video:{autoplay:false}`, `autoplay:{waitForVideo:true,delay:5000}`. Fixture задаёт готовое и играющее видео 0. Сравнить два свежих экземпляра. Первому отправить один DOM `ended`. У второго перед тем же событием подписаться через `slider.on('videoEnded', payload => log.push(payload.index))`. Подписчик только читает payload. Ожидается одинаковая история `slideChangeEnd === [1]` в обоих вариантах. Контроль даёт `[1]`, вариант с подписчиком даёт `[1,2]` и `realIndex === 2`, хотя DOM событие и payload индекса 0 были ровно по одному. Пара воспроизведена 3/3 в каждом из Chromium, Firefox, WebKit. Во время `emit` EventEmitter перебирает живой `Set`. При переходе Autoplay снимает текущий `videoEnded` handler и регистрирует следующий. Когда в Set остаётся пользовательский подписчик, вновь добавленный handler может попасть в тот же dispatch. Проверить семантику подписок, добавленных во время dispatch, вместе с заменой active-video listener. [Парный тест](../../tests/audit/event-regressions.ts), [9 повторов EREG](slider-deep/2026-10-31T21-40-45-686Z-full-v7jneT/ereg-001-crosscheck.json), [активный/неактивный источник и subscriber](slider-deep/2026-10-31T21-40-45-686Z-full-v7jneT/video-end-branch-crosscheck.json), [EventEmitter.emit](../../src/core/EventEmitter.ts#L58), [смена video listener](../../src/modules/autoplay/AutoplayModule.ts#L465).

## Автопрокрутка и владелец видео

**MEDIA-002/005/034 / TVIST-AUDIT-014. Ручной stop не переживает последующее взаимодействие.** Три карточки, `autoplay:{delay:400,pauseOnHover:true}`. Вызвать `slider.autoplay.stop()`, отправить `mouseenter` и `mouseleave`, продвинуть часы на 1000 мс. Ожидаются индекс 0 и `isStopped() === true`. Получен индекс 2. У публичного `stop` и внутренней очистки таймеров сейчас общий `local_stop()`. Внутренний `start()` использует эту же очистку при перезапуске. Согласовать состояние ручной остановки с защитами hover, focus, visibility и hold, сохранив возможность явного следующего `start()`. **RISK-07-009/010 / TVIST-AUDIT-033. Окончание неактивного видео засчитывается активному.** Три HTML video, `speed:0`, `autoplay:{waitForVideo:true,pauseOnHover:true,pauseOnFocus:true}`. Активен индекс 0. Включить hover и focus, отправить синтетический DOM `ended` видео с индексом 1. Снять одну причину паузы — индекс остаётся 0. Positive controls 006/007 отправляют `ended` активному owner и дают единственный переход после release. Независимый вариант без паузы и без публичного подписчика также сдвинул 0→1 от одного `ended` неактивного видео во всех трёх движках, по 3 повтора. ## Lazy и DOM клонов

**MEDIA-020 / TVIST-AUDIT-016. `loadAll()` пропускает картинки внутри ссылок.** Семь слайдов с `<a><img data-src="…"></a>`, включён `lazy`, вызвать `slider.lazyload.loadAll()`. В Chromium и WebKit вторая страница общего контекста унаследовала остановленное в 2050 году время, а новый контекст получил обычный Date и работающий RAF. Исторические timeout после clock-сценариев пересматривать по новым наблюдениям. Исправление относится к стенду. Каждая попытка проверяет `Date.isFake === undefined`, а smoke сохраняет отдельный trace каждой попытки. Для разбора открыть путь `traceArtifact` в конкретной строке `results.json`.
