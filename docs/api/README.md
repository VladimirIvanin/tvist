# Как собирается документация

Документация Tvist — статический многостраничный сайт на Vite. Исходный текст находится в Markdown-файлах `docs/guide/`, `docs/api/` и `docs/examples/`; страницы создаёт `scripts/build-docs.ts`.

## Команды

```bash
npm run docs:dev
npm run docs:build
npm run docs:preview
```

Единый справочник публикуется по адресу `/tvist/api/index.html`. TypeScript Compiler API читает `TvistOptions`, интерфейсы конфигурации и класс `Tvist`: типы, сигнатуры, комментарии, `@default`, `@example` и `@deprecated`. Члены с `@internal`, private/protected и служебные имена с `_` не публикуются. Для конструктора отдельно генерируется совместимый `docs/site/options-meta.json`.

## Как обновлять API

Краткие описания и значения по умолчанию редактируйте в JSDoc рядом с объявлениями. `@default` должен соответствовать реализации; без тега в таблице отображается `—`.

Пояснения и примеры добавляйте в `docs/api/reference.md` под заголовком второго уровня с точным ключом:

````markdown
## option:autoplay.delay

Задержка задаётся в миллисекундах.

```javascript
slider.updateOptions({ autoplay: { delay: 5000 } })
```
````

Допустимы ключи `option:имя`, `method:имя`, `property:имя`, `static:имя`, `event:имя`, `module:имя`, `type:имя`. Вложенные настройки используют полное имя через точку. Не повторяйте типы и сигнатуры — они извлекаются из кода. Имена записей становятся постоянными якорями (`option-autoplay-delay`, `method-scrollTo`).

События, пока не объявленные в `TvistOptions.on`, перечислены явно в `scripts/api-reference.ts`; их фрагмент начинается строкой ``Аргументы: `(img: HTMLImageElement, slideIndex: number)` ``. Перед добавлением сверяйте вызов `emit` в реализации. Для нового модуля добавьте его опции и связанные события в `apiModules` этого файла.

Сборка останавливается при неизвестном или повторном ключе, повторном якоре и несуществующей внутренней ссылке. `reference.md` не публикуется отдельной страницей. Старые страницы опций, методов, свойств, событий и статического API сохраняются как переходы с сопоставлением прежних якорей. Статьи TypeScript, breakpoints и создания модулей остаются отдельными.

## Живые примеры

Для каждой опубликованной демонстрации есть `docs/site/demos/<id>/markup.html`, `style.css` и `script.js`. Предпросмотр исполняет эти файлы в отдельном iframe, а посетитель видит и копирует их исходный текст. Каталог формируется из `docs/site/demos.json`.

Статические страницы сохраняют привычные адреса вида `/tvist/examples/basic.html`. Готовый сайт находится в `docs/dist/` и публикуется на GitHub Pages.
