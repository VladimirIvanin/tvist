# Первичные находки аудита

Production-код не изменён. Ниже перечислены классы находок, а не количество упавших тестов: одна причина может проявляться в нескольких сценариях и браузерах. Полные текущие результаты кампаний сохраняются отдельно; незавершённые прогоны не считаются пройденными.

Исследованный commit: `dea54d579239cd29224303c90646f00b577ec41c`. Для независимого Chromium-повтора использовалась изолированная сборка с JS SHA-256 `63f82928b9db2be2374e2824c62021aa8b7558d02658b8a2b8f87a421c234550`. Ниже не заявляется переносимость результата на реальные Safari/iOS устройства.

## Поведение, воспроизведённое в Chromium

| Класс | Минимальные cases | Наблюдение и воспроизведение | Классификация |
|---|---|---|---|
| AUTOPLAY-STOP | MEDIA-002, MEDIA-005, MEDIA-034 | Три слайда, `autoplay:{delay:400,pauseOnHover:true}`. Вызвать `autoplay.stop()`, затем mouseenter→mouseleave: индекс меняется с 0 на 2 за 1000 ms. `isStopped()` остаётся false. Отдельно long press после stop возобновляет движение при отпускании. | Нарушение смысла публичных stop/isStopped; несколько проявлений одной причины. |
| INSTANT-ACTIVE | MEDIA-024 | Семь слайдов с native lazy images, `nativeLazyAdjacent:true`; вызвать `scrollTo(5,true)`, дождаться settle. Индекс равен 5 и transform показывает пятый слайд, но класс active остаётся у нулевого. Целевая картинка правильно становится eager. | Рассинхронизация индекса и DOM-состояния; не ошибка самой загрузки изображения. Может дублировать другие geometry cases. |
| LAZY-NESTED | MEDIA-020 | Семь `<a><img data-src=...></a>` внутри слайдов, `lazy:{preloadPrevNext:0}`; вызвать `lazyload.loadAll()`. У всех семи вложенных изображений остаётся data-src. | Ограничение распознавания вложенного содержимого; требуется сверка обещаний документации перед объявлением API-регрессией. |
| CLONE-FORM-IDS | MEDIA-026 | Три слайда с label/for и input id, `loop:{withClones:true}`. После init имеются девять input с тремя уникальными id. | Проблема доступности/интеграции форм в clone-режиме. Не проверка переноса введённого значения между клонами. |
| LAZY-DESTROY | MEDIA-030 | Семь direct-child изображений с data-src, preload 0; destroy после init. У шести ещё не загруженных слайдов остаются созданные spinner-элементы. | Неполная очистка созданного DOM. |
| PAGINATION-KEYBOARD | MEDIA-032 | Включить generated pagination: созданные span-точки не имеют Tab-входа или keyboard handlers. Клавиатурой нельзя выбрать другую страницу. Тест допускает обычные Tab-доступные кнопки и roving tabindex с ArrowRight. | A11y capability gap по carousel pattern; не требование реализовать отдельно документированную неработающую опцию keyboard. |

Для AUTOPLAY-STOP статическое чтение показало, что `local_stop()` очищает таймеры, но публичный `stop()` не выставляет `local_stopped`. Для LAZY-DESTROY сначала очищается очередь, по которой затем пытается пройти удаление спиннеров. Эти наблюдения помогают локализовать воспроизводимый результат; исправления не применялись.

Артефакты первого прогона лежат в `.tmp/audit/2026-10-31T19-45-00-023Z-smoke/`. Независимый повтор использовал свежий browser context на каждый case. После добавления ожидания settle MEDIA-024 продолжил падать. Дополнительные cases MEDIA-031 (axe scan controls) и MEDIA-033 (hold pause/resume) прошли в этом повторе. Прохождение axe не отменяет отдельную проблему клавиатурной доступности pagination.

## Исправленная ошибка тестового стенда

MEDIA-008 первоначально ожидал, что visibility:hidden родителя обязательно скрывает root. Но `.tvist-v1--created` явно задаёт дочернему root visibility:visible — это допустимое переопределение наследования CSS. Fixture исправлен: root задаёт visibility:inherit перед скрытием родителя. В исправленном сценарии autoplay корректно останавливается и возобновляется. Старое падение MEDIA-008 не является подтверждённым багом Tvist и не должно попадать в known-failures.

Первый smoke документации ошибочно требовал `data-tvist-slide-index` у grid-страниц. Grid создаёт страницы без этого атрибута, а публичный `realIndex` в таком случае соответствует `activeIndex`. Oracle исправлен: для страниц без атрибута проверяется идентичность active DOM-элемента `slides[activeIndex]` и равенство двух публичных индексов; для обычных и loop-слайдов сохраняется проверка исходного индекса. После исправления grid проходит meaningful next в Chromium. Это исправление стенда, а не production-кода.

Проверены все 29 preview demos в Chromium, Firefox и WebKit: 87 сочетаний, 84 pass, 3 limitation, 0 функциональных failures в итоговой выборке. Найдено 102 экземпляра слайдера; 99 раз выполнен доступный next/prev с изменением публичного индекса, проверкой конечных DOM-координат, active identity и пересечения активного слайда с viewport. Единственные три limitations — намеренно locked пример в каждом движке: DOM проверен, недоступное движение не объявляется пройденным.

Документация собрана из изолированного snapshot, production-файлы и текущий docs build не изменялись. Отчёт [docs-results.json](docs-results.json) объединяет 58 завершённых Chromium/Firefox проверок первого запуска и 29 проверок отдельного WebKit-повтора. Скрипт проверяет равенство hash сгенерированной сборки перед объединением; `reused`, `executedThisRun`, `baseline` и fixture каждого результата сохранены явно. Итоговые артефакты: `.tmp/audit/docs/2026-10-31T20-07-42-245Z/`.

Первый частичный запуск `.tmp/audit/docs/2026-10-31T20-01-49-351Z/` сохранён: после семи успешных WebKit demos получены девять таймаутов инициализации, начиная с product-cards; оставшиеся 13 WebKit demos в том запуске не выполнялись. Во всех 29 примерах отдельного WebKit-повтора внешние изображения заменены локальным SVG, внешние CSS — пустым stylesheet, внешние fonts/media/прочие запросы заблокированы. Все девять таймаутов исчезли. Это зависимость сетевого стенда, а не девять подтверждённых production-багов; реальные CDN и воспроизведение сетевого видео этим повтором не проверены. Chromium/Firefox в объединённом отчёте использовали только блокировку Google Fonts, что также указано у результатов.

При завершении Chromium зависли Promise `BrowserServer.close()` и `kill()`; после ограниченных ожиданий завершён только PID браузера, запущенного данным аудитом. Две infrastructure-записи сохранены отдельно, поэтому итоговая CLI-команда вернула exit code 1 даже при нуле функциональных failures. Это не скрыто как зелёное завершение кампании. ## Нативное HTML-video: проверка контрактов после реального прогона

Источник результатов — [raw native run](../../.tmp/audit/2026-10-31T20-22-04-946Z-smoke-all-3834d553/results.json), manifest и trace/screenshot/HTML в том же каталоге. Запущены 3 cases × 3 движка × 3 повтора: 27 попыток. В Chromium и Firefox NATIVE-001 прошёл 3/3 в каждом движке; NATIVE-002 и NATIVE-003 воспроизвелись 3/3 в каждом. Девять попыток WebKit остановились в независимом codec preflight до создания Tvist. Таким образом, это 6 успешных product executions, 12 воспроизведений двух классов дефектов и 9 environment blockers, а не 21 production failure.

Fixture создан локально: silent WebM VP9, 320×180, 30 кадров, номинально 1 секунда, 23341 байт, SHA-256 `efbd8e2b244b4cedd4f0fbc202fc75b450097590cbd6b8f4e1a8561e670c7577`. Native VP8 MediaRecorder не завершил запись за 10 секунд; установленный Playwright FFmpeg закодировал локальные canvas JPEG frames в VP9. Это fallback, не подтверждение работы VP8. [Manifest видео](../../.tmp/audit/fixture-video.webm.json) фиксирует фактический codec и причину fallback. Тесты не подменяют `play`, `pause`, `currentTime`, `readyState` и media events. Независимый `<video>` до mount обязан декодировать этот же файл, получить ненулевые размеры и продвинуть время.

| Класс | Минимальный case | Наблюдение | Контракт и оценка oracle |
|---|---|---|---|
| NATIVE-VIDEO-CLONE-SELECTION | NATIVE-002 | Три video-слайда, `loop:{withClones:true}`, video autoplay/muted/loop/pauseOnLeave включены. Уже после init единственный играющий элемент относится к `card-0`, но его slide не пересекает viewport. Значение oracle: `playing:[{id:'card-0',visible:false}]`; перед чтением состояния реальное время воспроизведения превысило 0.12 сек. | Должно играть видео активного видимого слайда. Oracle сравнивает нативное paused-состояние и физические DOM-прямоугольники, не приватную Map и не только active class. При perPage=1 и отсутствии peek ожидание ровно одного видимого player обосновано. Дефект воспроизводится на первой проверке; последующие три запланированных next в этом case **не выполнены** из-за раннего failure. |
| NATIVE-VIDEO-LATE-READY | NATIVE-003 | Два слайда, первый содержит ещё не загруженное видео. Ответ на его отдельный URL удерживается Playwright route; слайдер полностью переходит на второй слайд, после чего отдаётся настоящий WebM. После native ready старое видео имеет `paused:false`, несмотря на `pauseOnLeave:true`. | Задержка сети является fixture; media API и события остаются нативными. Контракт pauseOnLeave прямо требует паузу при уходе. `autoplay` атрибута в исходной разметке нет, а текстовый второй слайд не содержит видео. Проверка paused обоснована; следующее assertion сброса currentTime не достигается, поэтому отдельное нарушение reset по этому run не заявляется. |

Публичные обещания находятся в [VideoOptions](../../src/core/types.ts#L144), [LoopOptions.withClones](../../src/core/types.ts#L340) и [документации video](../examples/video.md#опции-video). Для сочетания video и clones запрет или исключение в этих контрактах не обнаружены: clone-режим должен представлять оригинальные слайды, а video autoplay привязан к их активации.

Статическое чтение согласуется с наблюдаемыми причинами. В [scan/register](../../src/modules/video/VideoModule.ts#L281) каждый физический slide регистрируется по общему `data-tvist-slide-index`; [Map.set](../../src/modules/video/VideoModule.ts#L331) заменяет предыдущий элемент очередной копией. [LoopModule](../../src/modules/loop/LoopModule.ts#L465) добавляет хвостовые копии с теми же индексами. Активация затем берёт один элемент Map по realIndex, без выбора видимой физической копии. Это объясняет играющий хвостовой clone при неподвижном видимом оригинале в NATIVE-002.

Для NATIVE-003 [деактивация](../../src/modules/video/VideoModule.ts#L457) вызывает pause/reset, но не отменяет ожидающие ready listeners. В [local_safePlay](../../src/modules/video/VideoModule.ts#L506) поздний onReady снимает listeners и планирует doPlay через RAF без повторной проверки активного слайда. Это объясняет возобновление после ухода. Это два разных пути: выбор неверного физического элемента и устаревшее отложенное действие. Production-исправления не применялись.

WebKit дал `NATIVE_MEDIA_ENVIRONMENT: fixture: decoder=timeout, mediaError=none` за ~8.3 секунды. [HTML-артефакт preflight](../../.tmp/audit/2026-10-31T20-22-04-946Z-smoke-all-3834d553/NATIVE-001-webkit.json) содержит пустой body после очистки probe; Tvist instance ещё не создавался. Это не доказательство определённого codec rejection и не регрессия Tvist. Нативный video product coverage WebKit остаётся заблокированным до доступного decoder/другого валидного codec fixture; после этой классификации дополнительные повторы не выполнялись. Возможности реальных Safari/iOS, audio, full screen и качество декодирования не проверены.

## Как читать общую кампанию

- Raw failures не равны числу независимых production-багов. Дедупликация ведётся по нарушенному контракту и минимальной последовательности.
- Широкий `test.fail`, blanket skip и автоматическое заполнение known-failures не используются. Known-failures остаётся отдельным, вручную проверяемым механизмом.
- Синтетические HTML-media события проверяют логику состояния и освобождение ресурсов; они не подтверждают real codec playback.
- Результаты документации находятся в [docs-results.json](docs-results.json); package-consumer проверки — в [package-results.json](package-results.json). В docs-наборе locked/disabled/hidden экземпляры отмечаются как limitations, без фиктивного успешного движения.
