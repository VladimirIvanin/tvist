# Проверка полной браузерной сборки

`browser-build/tvist.min.js` содержит все встроенные возможности. Лимит — **100 000 байт вместе с баннером**, до сжатия. CSS проверяется отдельно от этого лимита. Динамической загрузки компонентов нет.

| Метрика | Исходная сборка | Первый этап | Текущая сборка |
| --- | ---: | ---: | ---: |
| JS с баннером | 149 859 байт | 99 162 байта | 93 253 байта |
| Gzip | — | 31 119 байт | 30 567 байт |
| Brotli | — | 27 293 байта | 26 878 байт |

Engine, геометрия, переходы и встроенные компоненты используют типизированные фабрики со состоянием в замыканиях. Tvist остаётся публичным классом. Фиксированный набор фабрик сохраняет порядок инициализации; отключённые компоненты отсекаются до выделения их состояния. Общий владелец ресурсов очищает подписки, таймеры и RAF. Его методы и методы общей поддержки компонентов разделяются между экземплярами через прототип; хранилища таймеров и RAF создаются при первом использовании. Сокращение имён свойств ограничено префиксом `__tvistInternal_`: пользовательские опции, события, payload и DOM-свойства не сокращаются. Поля внутреннего runtime и служебных объектов также используют этот префикс; публичный фасад сохраняет имена API. Пагинация использует общие расчёты и рендер для обычного и free-режима, сохраняя арифметику дробного perPage. Запас до лимита — 6 747 байт.

## Проверки

- `npm run build:browser` собирает файл заново, добавляет баннер и завершает процесс ошибкой при превышении лимита.
- `npm run check:browser-size` отдельно проверяет существующий артефакт. CI проверяет размер свежей сборки.
- 113 файлов unit/integration: 1191 успешный тест, один пропущен.
- Покрытие всех файлов `src/core/**`: 90,25% statements, 90,24% branches, 83,66% functions. Порог 80% закреплён в конфигурации.
- 90 E2E-проверок в Chromium, Firefox и WebKit использует минифицированный файл: drag, loop, переходы, callbacks, публичные интерфейсы, autoplay/video, breakpoints, эффекты, grid, scrollbar, дробный perPage и экспорт самостоятельной страницы.
- Проверка 12 экземпляров после изменения опций и disable/enable подтверждает отсутствие оставшихся DOM-подписок, наблюдателей, таймеров и RAF после destroy.
- 23 браузерные проверки документации; typecheck, lint, сборки библиотеки и документации.

## Измерение движения и ресурсов на первом этапе

Локальный headless Chromium 149, Ubuntu 22.04, Node 22.21.1. Сравнивались исходный файл из Git и новая минифицированная сборка при одинаковых CSS и разметке: 40 экземпляров, 12 слайдов, perPage 3, gap 8, loop, стрелки и пагинация. Visibility отключена, чтобы все экземпляры участвовали независимо от положения в viewport. Первое измерение инициализации исключено; приведены медианы следующих пяти запусков.

| Метрика для 40 экземпляров | До | После |
| --- | ---: | ---: |
| Инициализация | 70,1 мс | 68,6 мс |
| Destroy | 21,7 мс | 9,3 мс |
| Медиана интервала кадров | 16,7 мс | 16,7 мс |
| P95 интервала кадров | 16,8 мс | 16,7 мс |
| Записи style при переключении | 120 | 120 |
| Прирост JS heap с живыми экземплярами после GC | 866 244 байта | 1 918 024 байта |

Конечная позиция всех экземпляров совпала: −103 px. Кривая CSS-перехода и число записей style сохранены. Эти измерения описывают одну локальную конфигурацию, а не универсальные пределы производительности.

Замыкания увеличили JS heap примерно на 26 КБ на экземпляр в этом сценарии. Это компромисс размера файла: плавность и время инициализации сохранены, но расход JS-памяти вырос. Проверка очистки ресурсов выполняется отдельно и не опирается на приблизительные значения heap.

## Дополнительная оптимизация

После первого этапа сокращены имена оставшихся внутренних полей, объединены повторяющиеся расчёты и рендер пагинации, методы обслуживания ресурсов вынесены в общий прототип. Таблицы таймеров и RAF выделяются при первом использовании. Полный публичный API и DOM-классы сравнены с предыдущей сборкой; функциональность проверена на итоговом минифицированном файле.

Повторён тот же сценарий с 40 экземплярами, без параллельно запущенных тестов. В трёх прогонах менялся порядок сравнения сборок. В таблице приведены медианы показателей этих прогонов.

| Метрика | До дополнительной оптимизации | После |
| --- | ---: | ---: |
| JS с баннером | 99 162 байта | 93 253 байта |
| Запас до лимита | 838 байт | 6 747 байт |
| Прирост JS heap с живыми экземплярами после GC | 1 919 236 байт | 1 725 796 байт |
| Прирост JS heap после destroy и GC | 582 232 байта | 575 812 байт |
| Медиана интервала кадров | 16,7 мс | 16,7 мс |
| Записи style при переключении | 120 | 120 |

Расход JS-памяти с живыми экземплярами уменьшился примерно на 10%. Конечная позиция всех экземпляров осталась −103 px. Медианы инициализации между прогонами варьировались: 65,4–114,4 мс до и 98,3–138,4 мс после; в двух прогонах новая сборка запускалась медленнее, в одном быстрее. Эти измерения не подтверждают устойчивого ускорения инициализации. Прирост heap после destroy включает прогрев среды и выполнение измерительного кода; для проверки утечек отдельно проверяется очистка подписок, наблюдателей, таймеров и RAF.

Npm выпускает ту же полную библиотеку в ESM и CJS; файл CJS имеет расширение `.cjs`, определения типов находятся в `dist/types/index.d.ts`. Браузерная поставка — `tvist.min.js` и `tvist.css`. Команда `npm run build:browser` также сохраняет `tvist.min.js.gz` со сжатым итоговым JS, включая баннер, и выводит его размер.
